# Debugging / Issue Triage Prompt
```
排查任何问题前，先做三件事：
1. 先看证据再推测：把用户提供的现象、日志、截图逐条整理，逐字确认他们看到的是什么；不要凭记忆或经验先下结论。
2. 对照代码/实现：定位到相关模块后，先读现有逻辑，看看与用户描述是否吻合；如果两边不一致，优先相信数据，再找逻辑里可能的断点或遗漏。
3. 区分阶段/上下游：梳理同一条数据在不同阶段可能的表现（UI 渲染、缓存、后端存储、第三方输出等），明确本问题属于哪一层，不要把某一层的假设套到所有层。

在此基础上，才开始提出假设或修改方案，并在每一步都回到用户的实际数据验证。凡事“先事实、后推理”，避免自说自话。
```
